Linux & Systems: From Basics to Administration

Learn Linux concepts, the filesystem, shell, users, processes, services, networking, troubleshooting and system hardening.

Study in order, practise in a lab you own or have explicit permission to test, take notes, and revisit each level. Examples are educational; never run security tests against systems without authorization.

1 — What Linux is

Linux is the kernel; a distribution combines it with utilities, package management and applications. Examples include Ubuntu, Debian, Fedora, Arch and Kali. Kali is security-focused, but beginners can learn most Linux administration on Ubuntu or Debian.

Important concepts: kernel, user space, shell, terminal, process, service/daemon, package, filesystem, permissions, logs and system calls.

2 — Filesystem and navigation

pwd                 # current directory
ls -lah             # list files, including hidden
cd /var/log         # change directory
mkdir practice
touch notes.txt
cp notes.txt copy.txt
mv copy.txt archive.txt
cat notes.txt
less /var/log/syslog
find . -name "*.txt"

/ is the root directory; /home stores user homes, /etc configuration, /var/log logs, /tmp temporary files, /usr most user-space programs and libraries, and /dev device interfaces. Exact log paths vary by distribution.

3 — Permissions and users

whoami
id
groups
ls -l
chmod 640 notes.txt
chown user:group notes.txt   # requires suitable privileges
sudo command

Read/write/execute permissions apply to owner, group and others. Prefer least privilege; do not run every command as root. Understand rwx, numeric modes, ownership, sudo policy and why world-writable permissions can be dangerous.

4 — Packages, processes and services

# Debian / Ubuntu
sudo apt update
apt search package-name
sudo apt install package-name
sudo apt remove package-name

ps aux
top
pgrep -a ssh
kill -TERM PID
systemctl status ssh
journalctl -u ssh --since today

Use your distribution's official repositories. Confirm package names and service names for your system; avoid copying unfamiliar installation scripts directly into a root shell.

5 — Storage and system health

df -h
du -sh ~/Downloads
free -h
uptime
lsblk
mount
dmesg --level=err,warn

Learn partitions, filesystems, mount points, swap, disk usage, backups and restore tests. Before destructive storage commands, verify the device name and maintain a backup.

6 — Networking and remote access

ip addr
ip route
ss -tulpen
getent hosts example.com
curl -I https://example.com
ssh user@lab-host
scp report.txt user@lab-host:~/

Use SSH keys, disable password login where appropriate after testing access, restrict management ports and keep host keys verified. Do not expose admin services to the public internet without a reviewed security design.

7 — Bash scripting

#!/usr/bin/env bash
set -eu
printf 'Host: %s\n' "$(hostname)"
printf 'Date: %s\n' "$(date -Is)"
df -h /

Learn quoting, variables, exit codes, pipes, redirection, loops, functions and safe error handling. Test scripts on sample files before pointing them at important data.

8 — Hardening and troubleshooting

  • Patch regularly; remove unused packages and services.
  • Use unique accounts, MFA for remote-access portals, least privilege and strong SSH configuration.
  • Configure a host firewall with default-deny inbound policy where practical.
  • Review authentication logs, service logs, listening ports and scheduled jobs.
  • Use backups, time synchronization, disk encryption and recovery procedures.
  • Investigate in order: reproduce issue → check service status → inspect logs → check resource use → check network → document fix.

Practice plan

  1. Install a Linux VM and take a snapshot.
  2. Create users, groups, directories and files with appropriate permissions.
  3. Install a package, inspect a service and find its logs.
  4. Write a read-only system inventory script.
  5. Harden SSH/firewall in a lab and verify both allowed and blocked traffic.

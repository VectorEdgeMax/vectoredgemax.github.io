Security Tools: Practical Field Guide

A categorized guide to widely used security tools, what each does, and safe starter workflows.

Study in order, practise in a lab you own or have explicit permission to test, take notes, and revisit each level. Examples are educational; never run security tests against systems without authorization.

No single tool is “best” for every job. Choose based on the authorized objective, operating system, skill level, data sensitivity and maintenance status.

Network discovery and diagnostics

Nmap

Network inventory and service discovery. Start only with your lab target.

nmap -sn 192.168.56.0/24
nmap -sV 192.168.56.10

Use the lab subnet you control; service detection can generate traffic. Do not scan public ranges without authorization.

Wireshark / tcpdump

Inspect packets and troubleshoot protocols. Capture only traffic you are allowed to inspect; protect capture files because they may contain sensitive data.

tcpdump -i any -nn 'port 53'

OpenSSH

Secure remote administration and file transfer. Prefer keys, verified host keys, least privilege and restricted access.

Web and application security

OWASP ZAP

Open-source web application proxy/scanner. Configure a local training target, browse through the proxy, review passive findings, then run active tests only where explicitly allowed.

Burp Suite Community

Intercepting proxy for manually inspecting HTTP requests and responses. Use a test browser profile and training app; avoid intercepting other people's traffic.

Browser DevTools

Inspect DOM, requests, cookies, storage, console errors, performance and security-related headers.

Dependency and code scanning

Use tools such as Dependabot, pip-audit, npm audit, Semgrep and CodeQL to identify known dependency or code patterns. Review findings rather than treating every alert as a confirmed vulnerability.

Penetration-testing frameworks

Metasploit Framework

Modular framework with auxiliary, exploit, payload and post modules. Learn console help, module documentation and options in a disposable lab. A module's existence does not imply it is safe or authorized to run.

msfconsole
help
search type:auxiliary
info 
show options
exit

Impacket

Python tools and protocol implementations useful for understanding Windows network protocols in authorized labs. Because some features enable credential and remote-execution workflows, restrict use to approved test environments.

Host, forensics and monitoring

  • Sysmon: detailed Windows event logging when configured appropriately.
  • Wazuh: endpoint monitoring, log analysis and security visibility.
  • osquery: query system state with SQL-like syntax.
  • Velociraptor: endpoint visibility and digital forensics/response workflows.
  • YARA: pattern-based file classification for research and incident response.
  • ClamAV: open-source malware scanning for supported workflows.
  • Autopsy / The Sleuth Kit: forensic analysis of disk images and filesystem artifacts.
  • Ghidra: reverse engineering and binary analysis.
  • Trivy: scan containers, filesystems and configuration for known risks.

Cloud and wireless

  • Cloud CLIs and IAM analyzers: inspect resources and permissions in your own account.
  • Kubectl and kube-bench: administer and check Kubernetes configurations in a controlled cluster.
  • Aircrack-ng: wireless security assessment; only use networks and adapters you own or are authorized to test.

Tool-selection workflow

  1. Define a question before choosing a tool.
  2. Confirm scope and safe rate/impact.
  3. Read official docs and verify the version.
  4. Run a harmless check first and save output securely.
  5. Validate findings manually and report remediation.

Official learning references: Nmap manual, Metasploit docs, ZAP getting started, Wireshark docs.
